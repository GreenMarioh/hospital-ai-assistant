# Decisions & Assumptions
- **Python 3.14** (spec said 3.12): the dev host only has 3.14; all dependencies install cleanly on it. Images use `python:3.14-slim`.
- **Rootless Docker** used on the dev host (no sudo). Postgres published on host port 5433 because 5432 is taken.
- **Background jobs: APScheduler** in a dedicated worker process. Simpler than Celery+Redis; deduplication via the `notifications` table so restarts never double-send.
- **Caddy** replaces Nginx for TLS (automatic Let's Encrypt renewal).
- **RAG**: Postgres full-text search over `knowledge_base/*.md` (pgvector deferred).
- **Field encryption**: Fernet with key from env for insurance ID.
- **Least privilege DB**: `hospital_app` runtime role (DML only); `hospital_migrator` owns schema and runs Alembic.
- **Clinical data least privilege**: visits, prescriptions and AI summaries are readable only by the patient and by doctors with an appointment/visit relationship; admin and reception staff are excluded. Staff/admin see demographics; staff also upload and view documents. Unauthorized object access returns 404 to avoid leaking existence.
- **Versioning**: every edit snapshots the previous state into `record_versions` (immutable, with editor id) and bumps `visits.version`.
- **Documents**: PDF/PNG/JPEG only, 10 MB, magic-byte check, pluggable scanner hook (EICAR built in), downloads via 5-minute signed links; deletes are soft.
- **AI safety design**: rule-based red flags run before and independently of the LLM, are sticky per conversation, and short-circuit it (no LLM call on emergency). Output guard replaces replies that diagnose or recommend medication. Booking assistant tools are read-only; `propose_booking` only stores a proposal and the patient must call `/api/ai/booking/confirm`.
- **AI resilience**: 30 s timeout, 3 attempts with exponential backoff on 429/5xx/connection errors (not on 4xx), circuit breaker (5 failures, 60 s), degraded deterministic behaviour for triage, FAQ and briefings; booking chat returns 503 pointing to manual booking.
- **AI evals**: `python -m app.ai.evals.run [--live]`. Rule results are always measurable offline; LLM accuracy needs `ANTHROPIC_API_KEY` and is reported as NOT RUN otherwise. The cases were authored alongside the rules, so 100% rule recall is a coverage check, not proof of generalisation.
- **Model**: read from `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`); no sampling parameters are sent, and `ANTHROPIC_EFFORT` is optional.
